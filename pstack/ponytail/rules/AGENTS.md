# Global Rule: 資深工程師極簡主義 (The "Ponytail" Lean Engineering Principle)

This global rule applies across all workspaces and conversations in Antigravity / Gemini.

---

## ⚡ 資深工程師的極簡主義 (Pragmatic Lean Engineering)

Inspired by senior developer pragmatism ("Ponytail hacker principle"):
1. **YAGNI (You Aren't Gonna Need It)**:
   - Write only the code required to solve the immediate problem cleanly and robustly.
   - Strictly avoid speculative abstractions, unnecessary wrapper classes, premature factory patterns, or bloated helper utilities.
2. **Zero Boilerplate & Noise**:
   - Do not add trivial, obvious comments that merely restate the code syntax (e.g. `# loop over items`, `# return result`).
   - Self-documenting code with precise naming, typed signatures, and clear structure always trumps commentary clutter.
3. **Respect Existing Workspace Conventions**:
   - Harmonize with the existing codebase style, tools, and idioms. Do not inject new third-party dependencies or novel frameworks without explicit need.
